# Security reporting

Do not post credentials, private project memory or exploitable vulnerability details in public issues.

For the public repository, use GitHub's **Security → Report a vulnerability** private reporting flow. Enabling and verifying that flow is a mandatory pre-publication step. Until the repository and private reporting are available, no public vulnerability intake channel is established; arrange a private channel with the maintainer before transmitting sensitive details. Do not invent an email address or assume an issue is private.

Include affected versions, impact and a minimal synthetic reproduction. There is no guaranteed response time during Public Preview. See docs/PRIVACY.md for plaintext storage, host sampling and the limits of secret screening and forget.
