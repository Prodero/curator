## First workstream acceptance

- Detect client, OS/runtime, package and current settings; never guess a client or unsupported adapter.
- Existing Codex and experimental Claude adapters own writes, backup/ownership checks and recovery. No second installer/config engine.
- Preview selected host without writes; apply only its reviewed configuration. Preserve other MCP entries, instructions, intentional dev mode and existing wizard behavior.
- Block conflicts, corrupt/duplicate settings and interrupted operations; no force/adoption or silent global toolchain changes.
- Separate package installation, MCP/global launch configuration and explicit project initialization/memory changes.
- Current published baseline is 0.2.1; feature-detect new CLI flags. Do not reference an unpublished npm 0.3.0 artifact as available.
- Report saved configuration, restart pending and actual client connectivity separately. A simulated client or protocol test is not native host verification.
- Tests use disposable HOME/config/project fixtures; no real client settings, global packages, credentials or OAuth changes.
- Missing/incompatible Node or missing/broken npm are separate approved prerequisite stages within one concrete installation plan. Reuse compatible existing runtimes/managers; otherwise propose a verified official runtime in a new user-local directory. Do not silently change defaults, profiles, unrelated projects or dev setup.

## Memory and UI acceptance

- Open and lifecycle replies focus on task/context, not housekeeping counts or invitations to moderate memory. Remove the old moderation UI rather than renaming it a diagnostics dashboard.
- Existing deterministic synchronization, safe deduplication, provenance, transaction recovery and unchanged reruns continue automatically. Active sessions are never closed just to clear a counter.
- The current session's host agent receives only bounded source-bound reconciliation work. Responses are data, never authority or permission. Preserve protected rules, publication boundaries, complete source/history and exact operation receipts.
- Unsupported, ambiguous, incomplete or stale resolutions preserve original records and stop the bounded attempt. Ask one concrete question only when an unresolved policy/decision actually blocks the current task.
- Real save/storage/recovery errors remain visible and sanitized. Missing optional usage telemetry is not an error.
- Explicit Open exposes Curate Memory and selected Local → Versioned in both interfaces. Fresh curation preserves incompatible history, starts from current canonical knowledge without old approvals, and keeps protected Apply graphical. Shared writes require the complete exact preview and explicit approval; routine lifecycle never initiates these flows.
- Confirmed Close always has a short visible final receipt, including zero observations and deferred saving. Observations are not reported as newly created knowledge records.
