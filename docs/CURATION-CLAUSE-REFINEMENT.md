# Required clauses and attention evidence

## Previous behavior

`planKnowledgeCuration` previously inherited Required for every analyzed fragment except transient text and a fragment beginning `Workflow Note:`. It forced each inherited fragment to category instruction. The import analyzer also joined Impact and many Constraint fields to their Decision. Consequently commands, test-quality notes, implementation observations and explanations could become independently mandatory. This was a proposal rule, not an automatic canonical mutation.

## Current analysis

`curation-clauses.ts` is a curation-only refinement of the existing evidence-first analyzer. Importer v2 behavior is unchanged. Internal roles are constraint, invariant, convention, procedure, command, lesson, history, rationale and unresolved. These roles are not new canonical categories or authority values. Knowledge Schema remains v3.

Labeled source fields and complete sentences establish exact source ranges. Required is inherited only by identified normative constraints, invariants and conventions. Explicit supporting fields do not acquire mandatory policy through imperative grammar. An explicitly mandatory command can remain normative. A historical observation does not weaken a separate conditional constraint. Unstructured authored rules remain intact rather than being speculatively demoted.

Adjacent compatible clauses coalesce. Nonadjacent normative clauses from the same source and applicability are grouped into one output, while supporting text remains in coherent role groups. Outputs retain original text; mappings cover every source range and validate reconstructed content. This deliberately avoids creative compression. Supporting records retain source provenance, lifecycle, priority, relationships and legacy authority while receiving Relevant delivery policy. Every semantic change still needs exact trusted batch review.

This deterministic role classifier is conservative proposal analysis, not a general natural-language proof. Inseparable or conflicting normative meaning remains review work. Token savings never decide a role.

## Consolidation

The planner can consolidate source-identical normative cores only with identical applicability, scope, authority, priority and storage layer. Shared outputs union provenance and relationships. Every participating source must be selected in the same exact review batch; source retirement and output creation use the existing journal transaction. Different clauses, different scopes, or mere shared vocabulary do not establish equivalence. Paraphrase-based consolidation is intentionally not claimed as proven.

## Read-only evidence

`curation-evidence.ts` scans bounded test, handler, documentation, build and deployment directories. It reads source text only: no test execution, shell evaluation, configuration loading or project lifecycle calls. Vendor trees, caches, canonical memory, assets and symlinks are excluded. Each excerpt includes relative path, line and SHA-256. File count/depth/size ceilings bound work; truncated inspection is explicit in the plan.

Current tests can resolve a helper label into the actual API testing boundary. Named source domains plus matching implementation evidence can replace incidental DB/PHP/SKU labels. Historical observations can remain traceable Relevant history without asserting they are still true. Static test definitions do not establish a passing runtime or deployed production state. A current export test allowing fake queries/dispatch is evidence of architecture beyond an old blanket refusal; it does not authorize real integrations.

Evidence classifications distinguish resolved proposal, reduced ambiguity, genuine decision and historical-only. The original normative meaning remains protected even when implementation disagrees. Mirroring conflicts compare active Required knowledge, excluding historical lessons that merely mention failed mirror fixes.

Plans include evidence root, truncation status and source revisions. Apply rechecks referenced evidence bytes, in addition to canonical source revisions and the existing exact-plan trusted capability. Neither evidence, confidence, plan possession nor a boolean approval bypasses the exact-record Core policy checks. These internal checks do not authenticate human consent; the App adapter can issue the grant from a validated caller request. See [the v0.1 trust model](PRIVACY.md).

## Presentation and simulation

Shared UI/text presentation puts unresolved decisions before grouped suggestions. Evidence excerpts, hashes and full source/output content are in Details. No permanent panel or new Prepare interruption is introduced. Deferral uses the existing revision-bound recommendation lifecycle.

Simulation writes only disposable canonical copies and invokes the unchanged real context selector. Metrics now also include applicability decisions/reasons. Simulation uses the current [Context Selection v2](CONTEXT-SELECTION-V2.md) allocator: a default 6,000-token total, a 2,000-token Required reserve, 128-item / 16,000-token Required safety ceilings and a soft Relevant target of 8.

## Boundaries

- Static evidence cannot prove a historical PHPUnit error is resolved or production rollout completed.
- No new host-specific trusted review adapter is introduced. The existing trusted Core/embedding batch boundary is required for application.
- Exact repeated normative cores consolidate; differing fail-closed/harness/DB/export requirements are not merged merely to fit a budget.

## Validation

Synthetic clause/evidence/consolidation tests exercise the actual planner and context selector in temporary projects.
