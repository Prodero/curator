### Native-host diagnosis and smallest safe next step

The failed Codex invocation was a **child CLI process launched by this agent's
restricted `exec_command`**, not the user's already running host. Its logs name
`/Users/example/.codex/state_5.sqlite` and the state root
`/Users/example/.codex`, both outside this task's writable roots. Read-only
filesystem metadata shows ordinary owner-write POSIX modes on the file/directory;
no database contents, authentication files or private runtime state were read.
It then failed to initialize its in-process app-server with `EPERM`, before any
model-generated command or Prodero call.

The installed CLI help describes `--sandbox` as the policy for **model-generated
shell commands**, and `--ephemeral` as avoiding session-file persistence.
[Official OpenAI documentation](https://developers.openai.com/codex/non-interactive-mode)
also limits the latter claim to session rollout files; it does not promise a
write-free CLI startup. The observed state write rejection is consistent with
the **outer execution sandbox**. That is an inference from the path, writable
root policy and launch timing, not a finding that the user's Codex is broken.
The exact app-server syscall behind `EPERM` was not traced. No native re-execution
with broader permissions or configuration/state/permission workaround was tried.

For Claude Code, the supported read-only `claude auth status --json` additionally
returned `loggedIn:false`, `authMethod:none`, `apiProvider:firstParty`. This
describes the test CLI execution environment's available authentication; it does
not prove that a separate normal interactive environment has lost its login.
No login, credential-store inspection or authentication copying was attempted.

The minimal user step is to open a **new** native host conversation/terminal
against a disposable fixture, without restarting ongoing hosts. For Codex, ask
for exactly one read-only `prodero_open` with explicit projectRoot
`/tmp/curator-native-probe-qtv6ef12`, and no init/prepare/remember/settings/update
fallback. This tests normal host launch/tool availability outside the agent's
child-command sandbox. For Claude Code, first run its supported auth status in
the user's normal terminal; if it also reports no login, the user can sign in
