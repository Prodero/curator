## Result and boundaries

The source generator remains authoritative. The generated runtime guide and connected instructions-read output agree exactly. MCP initialization is a compact wayfinder requiring the full runtime guide before project operations; it no longer duplicates the complete routing/menu/approval paragraphs. Shared presentation constants and mandatory operational payloads deliver exact action bindings at the relevant screen.

The guide restores the bundle-only read-only exception: no Recall/Prepare/Record/Close/Sync/additional scan/Apply, and unresolved results when supplied evidence is insufficient. Ordinary work retains Prepare/Record/Close, readiness blockers, exact prepared snapshots, approved migration plus returned resume, and truthful lifecycle receipts. The index is only the last file fallback. Required authority, English durable prose with exact identifiers, explicit skill creation versus inferred candidates, Local/Versioned separation and exact-preview approvals remain explicit.

The Git sentence now names the subject: Curator tools do not execute commit/push; the coding agent follows current user scope and host approvals. This clarifies product boundaries and does not prove that the old ambiguous wording caused any historical approval rejection.

Skill Preview and Review are covered by the no-App text gateway. The callback receives the same freshly resolved invocation/local/shared mode as its wrapper. A full exact draft and approval guidance survive the generic presentation layer. Text or unavailable Apps use chat; UI retains the App and a complete conditional fallback, without another Core RPC. The human preview also identifies create/update/covered, the exact update target and any notice. Covered proposals do not request promotion approval. Consent, tamper, stale-candidate/target and replay guards remain in Core.

Existing canonical IDs use the storage contract for remember replacements, relationships, Local Forget and promotion selectors, including legacy names with hyphens. Newly generated identities retain their existing format. This does not change history semantics: replacements supersede instead of editing history, relation targets must be current, Local Forget retires, and Versioned retirement remains the revisioned reviewed repository-maintenance operation. Traversal and malformed IDs remain rejected.
