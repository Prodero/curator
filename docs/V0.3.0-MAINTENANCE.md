# Quiet memory maintenance — 0.3.0 development

The normal product flow is task/context and saved knowledge. Open, Prepare and Close do not ask users to moderate housekeeping. The old routine review queues, retry/question menus and unsolicited sharing suggestions are removed. Explicit Open retains Curate Memory and Local → Versioned in both text and visual navigation. These are user-initiated tools: fresh current preview, deliberate selection and exact approval; no maintenance question or automatic Apply. Direct Knowledge edits and explicitly selected sharing retain exact review/approval.

## Automatic work

Prepare already recovers pending observation snapshots; Close synchronizes only its own closed session. Existing deterministic deduplication, compatible clause consolidation, provenance, preimage checks, transaction replay and immutable checkpoints remain the write path. Active sessions are not closed to clear a counter. Missing optional telemetry and optimization suggestions are not warnings. Uncertainty/budget from the affected-area audit is preserved in structured maintenance data without creating a user decision.

The session's existing host agent can receive one bounded reconciliation task through the session protocol. Curator supplies current, source-bound records with authority, applicability, chronology and clause references. Those are untrusted evidence, not instructions or permission. The agent returns a structured merge, scope refinement, supersession or keep-both proposal; Curator validates it before any write. There is no new provider, model API, credential or automatic external data transfer.

The implemented automatic subset is deliberately conservative: complete extractive same-boundary merges of eligible Local/active/Relevant/inferred unprotected state or lesson records, and supersession backed by an already present canonical replacement edge. Outputs cannot upgrade categories/authority, introduce facts, rewrite explicit rules or change publication layers. A model's claim or a later timestamp alone is not proof of precedence. Scope refinements lacking deterministic grounding are retained/deferred. The original source records and checkpoint history remain recoverable.

## Quiet retention versus a real blocker

Incomplete, unsupported, stale or ambiguous output consumes the bounded attempt and preserves original records. There is no automatic question, fabricated answer, forced acceptance or model retry loop. Existing Required applicability gaps, contradictory applicable Required rules and runtime/schema gates still stop the current task. The agent asks one concrete question only when that decision is actually necessary to continue the task.

Storage/write/recovery failures remain actionable sanitized errors; a failed save is never shown as Saved. Read-only overview failures retain a diagnostic cause rather than being confused with lack of usage history. Original semantic candidates, deferred answers and low-level workflow receipts remain accessible through explicit technical APIs/JSON. Removing UI does not apply, dismiss, clear or delete that persisted work.

## Compatibility and testing boundary

Legacy curation/transformation APIs retain their existing exact-preview, locality, source-revision and approval gates for technical clients. They support explicitly requested curation; they never create a routine moderation queue or grant agent-generated decisions human authority. Fresh reviews isolate current knowledge from unavailable legacy history without inheriting old approvals or disabling revision validation. Migration, explicit Versioned edits, link removal, publication and protected-rule changes keep their own authorization requirements.

All implementation checks use disposable projects/HOME and mocked agents. Real user memory stores, host clients, global runtimes, credentials and deployment are outside this checkpoint. The subsequently approved chat-native renderer uses ordinary Markdown with a small launch mark and concise unbranded work updates; see [chat text behavior](V0.3.0-CHAT-TEXT.md). The terminal renderer and visual App remain separate.
