## Chain and failure boundary

1. **Lifecycle invocation.** Open creates Bootstrap Context, not a session.
   Substantial work should Prepare; ordinary history questions may use Recall.
   Finishing substantial work should record and Close. The selected native audit
   did invoke both lifecycle endpoints; later short explanatory turns used Recall.
   No missing Close can be inferred for other tasks from this one example.
2. **Core state.** Prepare returns session/context/readiness. Close returns the
   closed session, synchronization and learned state. The text renderer already
   handles healthy, blocked, deferred and failed outcomes. The text close label is
   **Session closed (`/08`)**, not the literal phrase Session Complete.
3. **MCP presentation.** `auto` resolves using the connection's Apps MIME capability,
   not device detection. Original lifecycle tools retain static App descriptors;
   the `prodero_text` gateway has no App descriptor and forces text delivery.
   Before this fix, the UI branch discarded its computed humanText for lifecycle.
4. **Chat relay.** A tool result is not automatically an assistant message. Previous
   generic instructions requested human-readable output but did not give explicit
   lifecycle relay timing. In the real turn, the agent proceeded with task commentary
   and a substantive final answer while omitting lifecycle text.
5. **Host display.** Tool-output hiding, an invisible App on the reported native surface, or
   collapsing older cards could contribute. None is proven by the available thread
   API. Historical negotiated capabilities, response bodies and iframe events are
   unavailable; no root cause specific to the reported device is claimed.

## Narrow fix

- App-resolved Prepare/Close now retain the **existing** renderer text and exact
  operational bindings in `presentation.text` / `presentation.operational`.
  The full context remains in Core result without a second copy in the App fallback.
  The same compact fallback is included in assistant-audience content. App metadata,
  card grouping and actual Core invocation are unchanged.
- Shared runtime instructions and lifecycle tool descriptions specify visible
  relay timing for **text delivery**: Prepare before continuing authorized work,
  Close before the final task answer. Auto resolved text follows the same rule.
- Explicit per-operation lifecycle text requests use `prodero_text`. When a user
  reports an invisible App, the already returned fallback can be relayed. Later
  operations re-read project settings; no sticky conversation preference is made.
  Existing returned text/snapshots are reused; no extra
  Prepare, Close or context retrieval is introduced just to display confirmation.
- Healthy Prepare remains automatic with no Continue question, approval or menu.
  Deferred saving stays deferred; failed Close has no fabricated successful receipt.
  Fallback is not duplicated when the graphical App is visible.

This supplies missing data and clarifies the existing text-delivery obligation.
It is **not** a deterministic host event hook and cannot force an agent or client
to display text. It adds no periodic screens, auto-Prepare/Close calls, preference,
or new user confirmation. Native verification is still required.
