## 1. Task brief: goal and user promises

Deliver a focused chat-first reliability release with six concrete outcomes:

1. **Improve Memory is reliable and understandable to a new user.** Analysis → understandable proposals/outcomes → visible selection/confirmation where required → result/remaining work. Retry, expired analysis, saved answers, deferred questions and restart have visible next steps without requiring knowledge of Core/MCP internals. This is a journey, not a requirement for exactly four screens or new approvals for already-eligible Local operations.
2. **The main memory operation is understandable.** **Curate Memory is the user-approved name**, now implemented across the shared text/App entry and copy. Improve & Share remains a historical audit alternative. Distinguish managing records, improving Local knowledge and preparing Versioned files; Curate must not imply automatic promotion/sharing. Improve Memory and Share Knowledge can remain actions within that entry point.
3. **Text mode is a first-class PRIMARY UX, not a graphical fallback or a status format.** Give attractive modern-hacker text higher product priority than decorative graphical expansion: strong hierarchy, deliberate rhythm/density, a short expressive header, clear statuses and menus, complete exact previews and actionable error reasons. Use chat-native messages, not pasted CLI sessions; avoid repeated huge blocks, giant ASCII banners, mandatory ANSI, Markdown tables and wide frames that break on mobile. The design checkpoint is resolved: implement the approved original Telemetry/Pulse baseline, not the later rejected HOME/block-bar variants. See the P03/P04 verification report for the actual renderer outputs and remaining host acceptance gaps.
4. **Status is readable and scriptable.** Human-oriented default and explicit stable `status --json`, preserving machine/project scope and meaningful exit codes.
5. **Update installs the core from an explicit terminal command.** In Codex/Claude, an available-version indicator and its action only explain `prodero update`. The CLI previews a verified exact npm target and destination, asks the user to finish work and close hosts, then explicitly confirms before synchronous npm installation and truthful verification/result. Non-TTY requires explicit documented acknowledgment and exact target. User restart follows; Open/Prepare separately offer required project migration. No detached self-updater, universal launcher, process registry or automatic host shutdown.
6. **Personal theme/mode changes do not write shared project configuration.** Leaving Git clean is necessary but insufficient: even rewriting identical shared config bytes is prohibited for a theme-only save. Shared policies remain versioned. The per-checkout file/resolver/downgrade design below is an engineering proposal awaiting approval, not a storage layout already chosen by the user. Preserve existing defaults and the user's current theme.

Do not describe requested analysis as an active background worker, a partial result as complete success, local Versioned file preparation as a Git push, an unavailable version check as up-to-date, or an issued update guide as an installed package.

## 3. Scope and invariants

### In scope

- Fix F1–F6, shared recovery/answer/action contracts, first-class primary text UX and coordinated terminology/help/instructions. Graphical functional usability remains required; decorative expansion is lower priority than text quality.
- Add local presentation overrides without moving shared policies or canonical knowledge.
- Human/JSON CLI status compatibility work, consumers and release notes.
- Actual terminal-only update for a narrow verified npm installation; instruction-only MCP/UI, truthful npm outcomes, preserved registrations/dev selection and separate migration.
- Synthetic protocol/browser/installation tests and exact-artifact acceptance on specifically named host/runtime tiers.

### Out of scope

- Memory-engine replacement, cloud services/accounts/Cloud Skills, general UI framework extraction, workflow undo, daemon/background reasoning, or host-agent cancellation guarantees.
- Automatic commit/push, automatic knowledge publication, unattended updates, automatic project enumeration/migration, sudo or automatic prefix/permission changes.
- Executing updates for linked/workspace-local installations, other managers (pnpm/yarn/Bun), ambiguous/external ownership, arbitrary package IDs/URLs or unknown executable provenance. These receive accurate manual fallback.
- Multi-manager updater, atomic npm package rollback, native Windows/other Node-major support expansion, blanket config ignore/untracking, automatic legacy shared-preference cleanup and decorative graphical feature expansion that displaces primary text work.

### Non-negotiable boundaries

- `projectRoot` is a checked selector, never authority; preserve existing workspace, nested-root, secret-screening and diagnostic boundaries for direct and nested text calls.
- Retain old MCP IDs, request fields, filenames and supported natural-language aliases. UI labels may change only after the naming decision.
- Preserve question/answer lineage, exact revisions/hashes, idempotency, correction limits, expiry, stale-input checks, transaction receipts and exactly-once recovery.
- Keep selection, review and approval distinct. Show complete wording/layer effects before exact approval; a menu number is not approval. Review signals are workflow safeguards, not authenticated human identity.
- Local/Versioned describe Git storage/sharing, not protection against the connected agent. Preserve existing eligible Local application and exact Versioned/promotion/link-repair review rules.
- Preference reads are side-effect-free; theme/mode saves never open shared config for writing or replace it. Updater operations never invoke project migrations, Sync or knowledge/skill writers.
