# Chat text — 0.3.0 development

MCP text is an assistant reply in ordinary Markdown. It has no terminal frame, fixed width, screen sequence or surrounding interface code fence. Compact Open alone has explicitly bound numbered actions. The one-line `›_ prodero` mark belongs only to an explicit launch/overview. It is a small variation of the existing `>_` identity, not an image or emoji system. No host-specific table tool is required.

The terminal renderer remains independent for CLI migration output and explicitly requested `plain:true` ASCII MCP fallback. Native App routing still depends only on advertised MCP Apps MIME capability. A client without Markdown rendering receives readable Markdown source; Curator does not invent a richer capability. The additive `presentation.textFormat` identifies `markdown` or explicit `terminal` fallback, not a newly negotiated capability. The machine installation wizard remains separate. Explicit Curate Memory and Local → Versioned actions are available in both chat and visual navigation; routine lifecycle never opens them.

## Explicit launch

Compact Open uses a small branch below the brand mark and four fixed actions. Example with synthetic values, not current project statistics:

> **›_ prodero** · **Drift Control**\
> ├─ Memory: 174 records\
> ├─ Local: 160 · Versioned: 14\
> └─ Context loaded: 1 instruction
>
> **1.** View memory\
> **2.** Review legacy instructions\
> **3.** Share selected memory via Git\
> **4.** Settings
>
> Choose a number or ask in your own words.

The relay agent translates interface prose into the conversation language, retaining the explicit numbers and exact tool bindings. A corresponding Russian example is:

> **›_ prodero** · **Drift Control**\
> ├─ Память: 174 записи\
> ├─ Local: 160 · Versioned: 14\
> └─ В контекст загружено: 1 инструкция
>
> **1.** Открыть память\
> **2.** Уточнить старые инструкции\
> **3.** Поделиться памятью через Git\
> **4.** Настройки
>
> Можно выбрать номер или написать запрос обычными словами.

Each stored-memory count comes independently from Core. Missing, invalid or unloaded values say not loaded, never inferred by addition/subtraction or replaced with zero. True zero remains visible without a warning. The instruction count comes exclusively from the instruction array supplied by a loaded bootstrap result on this Open. It is not the number of stored rules, task-selected context, conversation instructions or tokens. Missing/unloaded bootstrap evidence says the count is unavailable; an empty delivered array truthfully says zero. No future-context paragraph or extra retrieval is needed. Repeated Open describes its own result and never invents continuity with another Prepare snapshot.

Number bindings reuse exact actions and project roots in the current result. Stable identities are `memory=1`, `instructions=2`, `sharing=3`, `settings=4`; optional read-only update instructions use slot 5. Numbers are literal Markdown text, not an ordered list that might renumber missing slots. `presentation.operational.numberedActions` and `availableActions` contain the same displayed bindings. Selecting a number is a request to navigate or preview, never approval. Other results replace these aliases; pending answer/approval inputs take precedence. Natural-language requests remain supported. Skills keep their existing route and are not given a new text adapter by this change.

An uninitialized or unknown project retains its truthful state and initialization explanation without these initialized-project aliases. Explicit initialization retains its short success receipt. Expanded inspection and terminal fallback remain separate; ordinary lifecycle does not repeat the brand or Open menu.

## Work updates and explicit inspection

The healthy Prepare fixture now returns exactly:

> **Context Ready**
>
> Loaded 1 project instruction · 1 knowledge record · 1 skill.
>
> Continuing the task.

The corresponding Russian reply can be:

> **Контекст готов**
>
> Учтены 1 правило, 1 запись и 1 навык.
>
> Продолжаю работу.

Prepare counts come from the exact Required/Relevant/Skills arrays returned for this operation, including zero; they never come from stored totals, previous bootstrap context or parsed English copy. Repeated Prepare with the current session ID retains Core resumption behavior. Empty context explicitly says `Loaded 0 project instructions · 0 knowledge records · 0 skills.`

A synchronized Close with two observations returns `**Session closed** · Saved 2 observations.` Zero observations says `**Session closed** · No observations recorded.` A replay says `Session already closed` with the prior observation count; the count never claims that observations are new knowledge records. Deferred saving says `**Session closed** · Saving deferred.` The host relay must include this one-line receipt in its final assistant answer, including quiet/zero cases, rather than leaving it only inside a tool result or collapsible commentary. Without a confirmed closed state, output says `Session status unavailable`; failed saving and optional diagnostic errors remain visible. The mark/project header is not repeated at these steps. Exact context and maintenance protocol data remain available to the agent; display does not trigger another retrieval or reasoning loop.

Knowledge lists use naturally wrapping title/layer/category bullets, with exact page-local IDs retained in operation bindings. Outside compact Open, actions use names; numbers are usable only if this exact result displays their binding. Ambiguous duplicate titles require clarification. Complete selected records, exact review proposals and explicitly requested technical diagnostics remain inspectable. Fences are used only for literal source/code/evidence, never to frame the interface. Selecting a named action is not approval; existing full-proposal, revision and consent checks remain intact. Explicit terminal fallback alone displays and binds its numeric/letter aliases.

Project names, titles and diagnostic summaries are sanitized and escaped as Markdown data. No width truncation or manual wrapping is applied to English, Cyrillic, Unicode or long project names. Client layout controls wrapping; no cross-client pixel/mobile rendering claim is made. The ordinary launch and lifecycle still contain no memory-moderation queues, counters or housekeeping questions.

## Explicit memory management

Text Open labels Curate Memory **Review legacy instructions**, and promotion **Share selected memory via Git**. The visual controls retain their existing labels. This curation path previews supported splitting and applicability refinement of legacy Required instructions, without carrying over historical decisions or approvals. It preserves source history and does not change Local/Versioned layers. It is not a general rewrite of every note or a sharing operation. A malformed or unsupported saved review cannot break Open; it remains preserved, fails validation when addressed directly, and is described only inside explicit management diagnostics. The graphical flow stages no choices by default, displays Current/Proposed knowledge, then requires the existing exact reviewed Apply. Protected curation remains preview/simulation-only in text when the App approval channel is unavailable.

Local → Versioned starts with exact Local record selection and a complete read-only promotion preview. Text detail offers the same preview for the selected ID. Neither browsing nor preview applies, migrates or shares data. Only explicit approval of the exact current preview writes Versioned files; no commit or push occurs. Required migration, stale sources, missing access and write failures keep their existing guards.

If no successful Prepare session ID is known for the current task, the host must not invent one or close a different session. Missing-ID/not-found errors do not prove that the project has no other active sessions. No closure or saving may be claimed on a failed/unconfirmed call. Deferred status appears once, followed by its recovery sentence. Technical Close notices use the same truthful receipt and cannot promise that new knowledge was created.
